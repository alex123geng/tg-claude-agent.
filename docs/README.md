# Юнит-экономика WB — Скаут

Статический дашборд для накопления еженедельных финотчётов Wildberries и
расчёта юнит-экономики по логике листов «Юнит» / «Юнит (мес)» из исходной
Google-таблицы «РНП / ИП Фролов В.». Один сайт, без бэкенда: vanilla JS,
[SheetJS](https://sheetjs.com/) и [JSZip](https://stuk.github.io/jszip/) с
CDN, данные копятся в IndexedDB браузера.

## Запуск через GitHub Pages

Страница использует `IndexedDB` и ES-модули — оба требуют `https://`,
открыть `index.html` двойным кликом с диска (`file://`) не получится
(модули не подгрузятся, а часть браузеров блокирует IndexedDB для
`file://`). Нужно раздавать через GitHub Pages:

1. Слейте эту ветку в основную (или сразу настройте Pages на неё).
2. В репозитории: **Settings → Pages → Build and deployment → Source:
   Deploy from a branch**.
3. **Branch:** нужная ветка (`main` после мержа, либо прямо
   `claude/new-dashboard-weekly-reports-6j7rm1`), папка — **`/docs`**.
4. Сохраните — через 1–2 минуты сайт появится по адресу вида
   `https://<пользователь>.github.io/<репозиторий>/`.

Я не смог включить Pages сам — у этой сессии нет доступа к API/UI
настроек репозитория, только к git.

## Как это работает

1. **Себестоимость** задаётся один раз на артикул (вкладка
   «Себестоимость») — вручную или разовой загрузкой листа «Справочник»
   (xlsx или html-экспорт). WB её не знает и не присылает — дашборд её не
   меняет сам, только по вашей правке.
2. **Еженедельные детализированные отчёты WB** (.xlsx или .zip с xlsx
   внутри) загружаются на вкладке «Загрузки» — по одному или сразу
   несколько. Каждая загрузка **добавляется** к истории в IndexedDB, а не
   заменяет её. Повторная/пересекающаяся загрузка не создаёт дублей —
   дедупликация по стабильному ключу из полей строки отчёта (артикул,
   дата продажи, номер поставки/сборочного задания, тип документа, суммы
   выплаты/комиссии/логистики/хранения, Srid и т.д.).
3. Юнит-экономика **пересчитывается на лету** из накопленных операций +
   сохранённой себестоимости за любой период, для которого есть данные —
   вкладка «Юнит-экономика» (по артикулам или по месяцам, как «Юнит
   (мес)»).

Все данные — только в этом браузере. Экспорт/импорт JSON (вкладка
«Настройки») нужен, чтобы перенести историю на другое устройство или в
другой браузер — бэкенда нет.

## Формулы и их проверка по эталонным данным

За период и артикул, по накопленным операциям отчёта:

```
Продажи, шт     = Σ "Кол-во" по строкам с "Тип документа" = "Продажа"
Возвраты, шт     = Σ "Количество возврата" по всем строкам
Заказы           = Продажи + Возвраты
% выкупа         = Продажи / Заказы
Продажи до СПП   = Σ "Цена розничная с учетом согласованной скидки" (строки "Продажа")
Выручка          = Σ "К перечислению Продавцу за реализованный Товар"
Себестоимость    = Продажи, шт × себестоимость за ед. (из справочника)
Комиссия         = Σ "Вознаграждение Вайлдберриз (ВВ), без НДС"
Доставка         = Σ "Услуги по доставке товара покупателю"
Прочие расходы ВБ = Σ "Хранение" + Σ "Операции на приемке" + Σ "Общая сумма штрафов"
Налог            = по ставке из «Настроек» (УСН «доходы» % от выручки,
                    либо «доходы минус расходы» % от маржи за вычетом
                    прочих расходов ВБ) — ставка НЕ подставляется по
                    умолчанию, пока вы её не зададите, налог не считается
Маржа            = Выручка − Себестоимость − Комиссия − Доставка
Прибыль          = Маржа − Прочие расходы ВБ − Реклама − Налог
Маржа, %         = Маржа / Выручка
Рентабельность,% = Прибыль / Выручка
Все "за ед." колонки = соответствующий итог / Продажи, шт
```

В детализированном отчёте WB нет отдельного события «заказ» (есть только
реализованные продажи/логистика/возвраты) — поэтому «Заказы» считаются как
«продано + возвращено», то есть все отгруженные покупателю единицы,
неважно, выкупленные или нет.

**Что проверено на приложенных вами эталонных данных** (лист «Юнит (мес)»
за июль 2026, один пример еженедельного отчёта):
- Соотношение Заказы/Возвраты/% выкупа (продано+возвращено) даёт те же
  порядки величин, что и контрольный месяц (29% в эталоне против ~29–32%
  на расчёте по формуле).
- Цепочка **Прибыль = Маржа − Прочие расходы ВБ − Реклама − Налог**
  совпала с эталонной строкой листа «Юнит» **день в день, до рубля**.
- Все «за единицу» колонки (себестоимость/комиссия/доставка/маржа/прибыль
  на ед., цена до СПП, % СПП) — тоже совпали до рубля: это всегда
  соответствующий итог, делённый на «Продажи, шт».

**Известное ограничение**: саму **Маржу** (Выручка − Себестоимость −
Комиссия − Доставка) сверить до рубля не удалось. На единственной строке
эталона, которую можно было проверить арифметически, результат по этой
формуле оказался примерно на 4% выше эталонного значения. У нас не было
доступа к первичным операциям за весь исторический период этой строки
эталона (в наличии — только один пример недельного отчёта, а не полная
история месяца/года), поэтому выявить недостающую составляющую не
получилось. Формула реализована буквально так, как задана в исходном
ТЗ. Когда в дашборде накопится полный месяц реальных загрузок — сверьте
Маржу с тем же месяцем в исходной таблице; если расхождение
систематическое, скорее всего не учтена ещё одна статья расходов (кандидат
по счёту: отдельная стоимость логистики возврата, отличная от
«Услуги по доставке товара покупателю» — в примере расхождение было близко
к 50 ₽ × количество возвратов, но подтвердить это некому было доступными
данными).

## Реклама — не в этой версии

Расходы на рекламу WB отдаются отдельным отчётом («Реклама» по кабинету),
который не подключён — колонки «Реклама», «ДРР, %» и «ROMI, %» показывают
«нет данных» вместо нуля. «Прибыль» и «Рентабельность» считаются без учёта
рекламных расходов. Если понадобится — отдельная доработка: нужно решить,
как парсить рекламный отчёт (в оригинале — 30–40 МБ, тяжело для браузера).

## Данные хранятся в IndexedDB

- `costRef` — себестоимость по артикулу (сопоставление между отчётами и
  справочником — без учёта регистра: WB сам путается в написании
  артикулов между разными выгрузками).
- `weeklyOps` — накопленные строки отчётов, с дедуп-ключом.
- `uploadsLog` — история загрузок (что добавилось / что было дублем),
  можно откатить конкретную загрузку — операции этой загрузки удалятся
  из истории.
- `settings` — налоговый режим/ставка.

## Известные ограничения

- Полная сверка «до рубля» была возможна только частично — см. раздел про
  Маржу выше. Проверяйте на своих полных данных.
- xlsx-библиотека (SheetJS) с cdnjs закреплена на 0.18.5 — в ней есть
  публичные advisories (prototype pollution, ReDoS), патчи для которых
  SheetJS публикует только на собственном CDN, не на npm/cdnjs. Здесь это
  принято как риск: страница без бэкенда, парсит только ваши же выгрузки
  из личного кабинета WB, а не файлы от посторонних. Если нужно закрыть
  и это — замените `<script src="https://cdnjs.cloudflare.com/ajax/libs/xlsx/0.18.5/xlsx.full.min.js">`
  в `index.html` на актуальную сборку с `cdn.sheetjs.com` (проверьте её
  перед выкладкой).
